# PIV Analysis Conditions (as actually used)

`doc/piv_preprocessing_protocol.md` が「どう処理するか」の手順書なのに対し, この文書は
**24 run で実際に使われた PIV 解析条件を設定ファイルから抽出した記録**である.
原稿の Table `tab:piv_settings` と §Surface PIV の数値はここを正本とする.

抽出元 (いずれも run ごと):
- `local/work/<run>/PIVlab_setting.mat` — GUI 設定の正本
- `local/work/<run>/piv_manifest.csv` — フレームレート・対間隔の記録
- `local/work/<run>/pivlab_single.mat` — 出力場 (格子, `typevector`)

抽出日 2026-07-27. R0001-R0024 の 24 run すべてに設定ファイルが存在する.

## 1. 設定は 24 run で完全に同一 (Δt を除く)

`time_inp` (画像対間隔) だけが条件ごとに異なり, **他の全キーが 24 run で同一値**だった.
run 間比較の前提が設定レベルで保証されている.

## 2. 校正と格子 (相互に整合)

```
1 px           = 1.9667 mm          (calxy = 0.00196669 m/px)
最終パス窓 32 px = 62.9 mm
格子間隔  16 px = 31.47 mm
ベクトル格子     = 92 x 61
格子の範囲       = x 0.0452-2.9087 m, y 0.0413-1.9293 m
```

設定ファイルの `calxy`, 出力場 `piv.x/piv.y` の実測間隔, `config/constants.m` の
`omega_x_m = [0.045, 2.909]` / `omega_y_m = [0.041, 1.929]` / `omega_grid_dx_m = 0.0315`
は互いに整合する (すべて `calxy` 由来なので当然でもある).

### 2b. 水槽内寸は 2.952 m x 1.962 m — 「3.0 x 2.0 m」は誤り (2026-07-27 確定)

実験者への確認で内寸が **295.2 cm x 196.2 cm** と判明した. これで校正の整合が取れる.

| 記録 | 値 | 判定 |
|---|---|---|
| PIVLab `realdist = 2952` mm | 内寸の実測値 | **正しい** |
| PIVLab `calxy = 1.96669` mm/px | 2952 mm / 1501 px | **正しい** (真値 x 1.9680 に対し -0.07%, y 1.9620 に対し +0.24%) |
| `rectification.mat` `pixel_size_m = 0.002` | 出力画像サイズ Nx x Ny の算出にのみ使用 | **ラベルとしては誤りだが速度には無害** |
| 原稿・README の「3.0 m x 2.0 m」 | 呼び値 | **誤り** (面積を 3.6% 過大) |

**速度データは正しい.** `pixel_size_m` は `select_rectification_points` で
`Nx = round(Lx/pixel_size)+1` を決めるためだけに使われ, 速度と座標は PIVLab の `calxy`
由来なので, 「2 mm/px」というラベルは下流に伝播しない. 誤差は ±0.25% 以内である.

副作用として, 真の 2952 x 1962 mm を 1500 x 1000 px 間隔に写しているため
x 1.9680 / y 1.9620 mm/px の **0.31% の異方性**が入っている. 単一の `calxy` では
これを表現できないが, 0.3% は他の誤差要因より小さいので実用上は無視できる.

独立な裏付け: グリッドの壁からの内側余白は, 真の内寸で見ると
x 側 0.045 / 0.043 m, y 側 0.041 / 0.033 m とほぼ対称になる. 「3.0 x 2.0 m」を仮定すると
x 0.045 / 0.091 m, y 0.041 / 0.071 m と 2 倍近く非対称になり不自然だった.

### 2c. 伝播していたのは平面積 — 実験の Q が 3.6% 過大だった

`config/constants.m` の `Aplan_m2 = 3.0 x 2.0 = 6.0` が真値 5.7918 より 3.6% 大きく,
`Q = A_plan x |dh/dt|` の形で実験側の流量に入っていた.

| 量 | 誤差 | 影響先 |
|---|---|---|
| `Aplan_m2` | +3.59% | |
| `q_actual_Lps` (s31) | +3.47% | `band_metrics.csv` の該当列 |
| 遷移時間法の `Q_act` (s33, 実験側のみ) | +3.47% | |
| `E / Up_act^2` (実験側のみ) | **-6.82%** | CFD 比較 |
| `I_asym`, `I_circ`, `I_rot`, 支配符号面積, 偏り指数 | **影響なし** | 無次元比・渦度はスケール不変 |

s33 は同じ `dV_band` を実験と CFD の両方に使っていたが, **CFD メッシュは実際に
3.0 x 2.0 m で作られている**ので CFD 側は 6.0 が正しい. 両者を分離した (2026-07-27 修正).
これにより「CFD の E は実験の 2-3 倍」という比は 6.8% 縮まるが, 結論は変わらない.

CFD メッシュ自体は作り直さない: アスペクト比が真 1.5046 vs メッシュ 1.5000 で 0.31% しか
違わず, 実質は真の盆地を 1.6-1.9% 拡大した相似形である. 流動レジームの議論には影響しない.

**再計算済み (2026-07-27)**: 24 run で s31 → s32 → s33 を再走した.

- `band_metrics.csv` の変化は **`q_actual_Lps_mean` の 1 列のみ** (100 行中 96 行, -3.47%).
  他の全列はビット一致. `band_id` も全 run 一致 — 水位由来の量は平面積に依らないという
  想定が実測で確認された.
- 実験側の `E / Up_act^2` は **+7.32%** (Q が -3.47% なので Up² が -6.71%).
- 深水帯の CFD/実験 比: **B3 が 2.05x → 1.91x, B4 が 2.20x → 2.05x**.
  「深水で CFD が約 2 倍」という診断はそのまま成立する.
- inflow medium の全バンド判定 (C0001 vs R0005-R0008):

  | band | E/Up_act² 実験 | C0001 | 判定 |
  |---|---|---|---|
  | B1 | 0.419-0.505 | 0.119 | 0.28x low |
  | B2 | 0.165-0.415 | 0.060 | 0.36x low |
  | B3 | 0.072-0.080 | 0.153 | 1.91x high |
  | B4 | 0.043-0.048 | 0.099 | 2.05x high |

  浅水で低く深水で高い交差構造は面積修正の前後で変わらない.

## 3. Δt の選定 — inflow は揃っている, outflow は揃っていない

| mode | level | Q [L/s] | Δt [ms] | Δt x Q |
|---|---|---|---|---|
| inflow | low | 0.25 | 200.2 | 50.05 |
| inflow | medium | 0.50 | 100.1 | 50.05 |
| inflow | high | 0.75 | 66.7 | 50.03 |
| outflow | low | 0.25 | 333.7 | 83.4 |
| outflow | medium | 0.50 | 333.7 | 166.9 |
| outflow | high | 0.75 | 333.7 | 250.3 |

**inflow は Δt x Q が厳密に一定** — 粒子像変位を条件間で揃える教科書的な選び方であり,
inflow 3 水準の比較は変位の面で対等である. 一方 **outflow は Q に関係なく全て 333.7 ms**
なので, 変位は水準間で 3 倍ばらつく.

なお 24 run すべてで `time_inp` と manifest の `dt_pair_s` が厳密一致した (食い違いなし).

## 4. 実測変位 — outflow がノイズ床以下である理由の定量

変位 = `mean_speed_mean` x Δt / 1.9667 mm.

| mode | level | <\|u\|> [m/s] | 変位 [px] | 最終窓 32 px に対する比 |
|---|---|---|---|---|
| inflow | low | 0.0095 | 0.96 | 0.030 |
| inflow | medium | 0.0193 | 0.98 | 0.031 |
| inflow | high | 0.0379 | 1.29 | 0.040 |
| outflow | low | 0.0003 | **0.05** | 0.002 |
| outflow | medium | 0.0004 | **0.08** | 0.003 |
| outflow | high | 0.0009 | **0.16** | 0.005 |

- **inflow は約 1 px** — 相関解析としては小さい (窓の 1/4 = 8 px が定石) が, 測れている.
  精度はサブピクセル推定器の性能でほぼ決まるので, peak-locking の確認は一度やる価値がある.
- **outflow は 0.05-0.16 px** — 一般的なサブピクセル精度 (~0.05-0.1 px) と同程度かそれ以下.
  つまり **outflow の速度場は原理的にノイズ床である**. 「outflow のバンドが解像できない」
  という既知の経験的問題に, ここで初めて定量的な原因が付いた: Δt の選定である.
- **再実験は不要**: 元動画は 29.97 Hz で残っているので, 対間隔フレーム数を増やして
  再エクスポート・再 PIV すればよい. inflow の ~1 px に合わせるなら
  outflow low で Δt ~6.7 s (200 フレーム), high で ~2.0 s (60 フレーム).
  排水は 0.10→0.03 m で 1700 s 級なので, 数秒の対間隔でも準定常性は保てる.
  ただし面外運動と水位変化の影響は事前に 1 run で確認すること.

## 5. ベクトル品質 — 記録している指標が飽和している

`piv.typevector` の意味: 1 = 実測, 2 = フィルタ後に補間, 0 = マスク.

| run | 実測 (TV=1) | 補間 (TV=2) | マスク (TV=0) |
|---|---|---|---|
| R0001 (inflow low) | 97.14% | 2.86% | 0% |
| R0005 (inflow med) | 98.23% | 1.77% | 0% |
| R0006 (inflow med) | 98.68% | 1.32% | 0% |
| R0007 (inflow med) | 98.74% | 1.26% | 0% |
| R0008 (inflow med) | 99.05% | 0.95% | 0% |

inflow の実測率は 97-99% で健全. ただし **記録している 2 つの品質指標はどちらも飽和して
使えない**:
- `valid_fraction` = 有限値の割合 → 補間後に評価するので全 run 1.000
- `typevector_nonzero_fraction` = TV≠0 の割合 → 1 と 2 を区別しないので全 run 1.000

意味があるのは **TV==1 の割合**なので, `compute_frame_metrics_basic` に
`typevector_measured_fraction` を足すのが妥当 (計算はすでにある `TV` の比較だけで済む).
outflow は Mac 側に `pivlab_single.mat` がないため未計測 — WS/ラボ機で要確認.
上の変位から, outflow の実測率は inflow より大きく落ちるはずである.
