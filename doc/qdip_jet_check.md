# 流量の谷の検証 — 水位から出す Q と PIV の噴流速度

**状態 (2026-10-15)**: LT で inflow 12 本中 5 本 (R0001 low, R0005-R0008 medium) を確認済み.
5 本とも「谷は流量低下ではない」側. **WS で残り 7 本 (R0002-R0004, R0009-R0012) を確認する** (§5).
スクリプト: `scripts/checks/qdip_jet_check.py` (検証専用の Python ツール. s10-s40 のパイプラインには入らない).

## 1. 問題

- 水位から出す流量 `Q_level = A_plan x |dh/dt|` (A_plan = 5.7918 m^2, ロガーは 1 mm 刻み) を
  5 mm 窓の滞在時間法で出すと, inflow 全 12 本で h ≈ 44-50 mm (h/a ≈ 0.85) に深い谷
  (名目の約 0.35 倍) がある. 形は low/medium/high で重なり, 所要時間が 3 倍違っても同じ水深に出る
  (経過時間ではなく水深で決まる). outflow にも浅く広い谷 (約 0.7 倍, h/a ≈ 0.8-1.0) がある.
- 帯平均ではこれが見えない: B1 (30-50 mm) は約 1.2 倍の区間と約 0.35 倍の区間を混ぜている.
- 問い: 谷は **ポートから入る流量が本当に減った** のか, **水位から体積への換算の見かけ**
  (水位計の読み, または水槽側の貯留) なのか.
- 重要な理由: 本物なら h/a ≈ 1 遷移にポート水没・給水路満管に次ぐ 3 つ目の交絡 (流量) が加わる.
  見かけなら, 水位由来の Q (`q_actual_Lps`, `Q_transit_Lps`, s33 の `Q_act`) は B1/B2 で使えず,
  水位計が原因なら深さラベル自体がずれる (B1/B2 境界 50 mm).

## 2. 方法

水位を経由しない独立な物差しとして, ポート噴流の表面速度を使う.

- **原理**: h < a ではポート出口の平均流速は `U = Q / (b h)`. 谷の前後で h は 2 割も変わらないので,
  Q が 1/3 になれば U もほぼ 1/3 になる. 噴流は 10-17 s で x = 0.5 m に届くので,
  140-490 s 続く谷には十分追従できる.
- **噴流指標 (proxy)**: ポート直近 (x < 0.15 m) は PIV が噴流を捉えていない (表面速度 ~0.01 m/s).
  そこで x = 0.19-0.52 m で, 5 s ブロック平均場の各 x 断面での最大速度をとり x 方向に平均する (`core`).
  補助に `frame_max` (フレームごとの最大値のブロック平均) と `jetflux` (噴流軸 ±3 セルの表面流束 Σu dy).
- **深さの窓 [mm]**: ref 32-38, pre 38-42, dip 44-50, post 56-62, B3 62-75, B4 75-95.
  各ブロックの深さは `frame_metrics.csv` (s31 の対応づけ) を使う.
- **主検定**: h = 35-62 mm のブロックで `log(proxy)` を `log(Q_level)` に回帰した傾き β.
  95% 区間は 60 s 単位の moving-block bootstrap (2000 回). 谷が本物なら β ≈ n (下の感度),
  見かけなら β ≈ 0.
- **感度 n**: 同じ深さ窓で流量水準間の比をとり `n = ln(proxy 比) / ln(Q 比)`.
  指標が流量計として働くか (とくに dip 窓で) の確認.
- **流量一定の基準**: CFD C0001 (0.50 L/s 一定) と D02 (0.75 L/s 一定) に同じ指標を当てる
  (PIV の 63 mm 窓をまねて 3x3 セル = 60 mm で平滑化). 流量一定でも水深だけで指標がどれだけ動くかの幅を与える.

## 3. LT での結果 (2026-10-15, 5 本)

主検定 (β, 括弧は 95% 区間):

| run | level | β (core) | β (frame_max) | Q_level の変動幅 | 判定 |
|---|---|---|---|---|---|
| R0001 | low | -0.08 [-0.17, -0.01] | -0.05 [-0.17, +0.03] | x3.6 | dip-not-followed |
| R0005 | medium | -0.11 [-0.15, -0.03] | -0.10 [-0.20, -0.03] | x3.3 | dip-not-followed |
| R0006 | medium | -0.07 [-0.24, -0.01] | -0.06 [-0.27, +0.03] | x3.8 | dip-not-followed |
| R0007 | medium | -0.13 [-0.27, +0.01] | -0.10 [-0.14, -0.01] | x3.0 | dip-not-followed |
| R0008 | medium | -0.17 [-0.27, -0.06] | -0.13 [-0.18, -0.06] | x2.6 | dip-not-followed |

谷が本物なら β は +0.8 から +1.1. 実測は 5 本とも負で, 95% 区間の上限も +0.03 以下.

- **感度 n (medium/low)**: ref 0.82, pre 1.03, dip 0.84, post 0.99, B3 0.98, B4 1.11.
  dip 窓でも指標は流量にほぼ比例して反応する. ただし low は R0001 の 1 本だけ.
- **流量一定の基準 (ref 窓に対する比)**: C0001 は pre 0.82, dip 0.81, post 1.09, B3 1.18, B4 1.00
  (dip/pre 1.00). D02 は pre 0.78, dip 0.92, post 0.70, B3 0.89, B4 0.94 (dip/pre 1.19).
  谷を本物とみなすには, 指標が dip 窓だけで水深により直前比 1.6-2.1 倍, ref 比 2.1-3.0 倍
  持ち上がる必要がある (n = 0.84-1.0 で計算). CFD ではそうならない.
- **V 字なし**: 実測の `Q_level` は dip/ref = 0.30-0.52. 指標側は W2 (0.19-0.52 m) で
  core 0.92-1.24, frame_max 0.90-1.14, jetflux 0.91-1.85. 噴流の幅を含む流束も落ちないので,
  「速度は保たれたが噴流が細くなった」もない. W1 (0.07-0.25 m) はばらつきが大きい
  (core で 0.58-1.54). 最低値の R0006 は谷の後もさらに下がり (post/ref 0.46), V 字ではない.
  W3, W4 (0.50-1.25 m) は水深とともに単調に減り (dip/ref 0.52-0.96, post/ref 0.38-0.82), 戻らない.
- **計測上の不具合なし**:
  - PIVLab に速度の上下限フィルタはない (標準偏差 6σ, 局所中央値 3, 相関 0.5 のみ).
    R0005 の噴流付近の速度分布は 0.126 m/s まで滑らかで, 頭打ちの溜まりはない.
  - 有効ベクトル率は ref 0.92-0.94, dip 0.97-0.98.
  - 噴流軸は y = 0.73-1.31 m (ref), 0.93-1.07 m (dip) で, 読み込み範囲 0.38-1.66 m の内側.
  - PIV とロガーの長さは 4 本で 0.3 s 以内. R0006 だけ PIV 1002.0 s に対しロガー 1008.2 s
    (6.2 s, 正規化時間の対応づけで 0.6% 伸びる). 谷の長さに比べて無視できる.

スクリプト外で確かめたこと (同日):

- 水位計の生信号は停滞中も 1 分あたり 10-23 回変わっていて (波を拾っている), 固着ではない.
  物理的にありえない跳びもない. 水位計が原因なら「固まる」故障ではなく「尺度がゆがむ」型.
- 40-60 mm で欠けている体積は基準線の取り方で大きく変わる: inflow 14-117 L, outflow 1-33 L.
  inflow と outflow で釣り合っていない.

## 4. 判定基準

スクリプトの `verdict` 列 (run ごと):

- `low-power`: 回帰範囲で `Q_level` の変動が 2 倍未満.
- `dip-not-followed`: core と frame_max の β の 95% 上限がともに 0.5 未満 (谷は流量低下ではない).
- `dip-followed`: core と frame_max の β がともに 0.6 以上 (谷は本物. LT の結論が覆る).
- `inconclusive`: それ以外.

全体としては次の 3 つが揃えば確定とする.

1. 全 run が `dip-not-followed`.
2. `calibration.csv` で, 各水準ペアの dip 窓の n が 0.6 以上 (指標が流量に反応している).
3. `run_summary.csv` の `dur_diff_s` (PIV とロガーの長さの差) が全 run で 10 s 以内.
   超える run は時刻対応を確認してから判定する.

1 本でも `dip-followed` が出るか, `timeseries.png` で噴流指標に「落ちて戻る」V 字が見えたら覆る.

## 5. WS での実行手順

1. `git pull` (ブランチ `cfd-campaign`).
2. 環境: Python 3.8 以上, numpy, h5py, matplotlib.
   `python3 -c "import numpy, h5py, matplotlib"` で確認し, 無ければ `pip install h5py matplotlib`.
3. 入力 (run ごと, data root の下):
   - `raw/<run>/waterlevel.csv` (ロガー生データ)
   - `derived/metrics/<run>/frame_metrics.csv` (s31 まで済んでいること)
   - `work/<run>/pivlab_single.mat` (s20 の正規化済み PIV)
   - 任意: `work/C0001/pivlab_single.mat` と `derived/metrics/C0001/frame_metrics.csv`,
     `work/D02/surfSample/` (CFD の流量一定基準. 無ければ飛ばす)

   data root が `<repo>/local` でなければ `--data-root` で指定する.
4. 実行 (リポジトリのルートで):

   ```bash
   python3 scripts/checks/qdip_jet_check.py
   ```

   inflow の全 run を対象にする (入力が揃わない run は理由を表示して飛ばす).
   1 run あたり数秒から十数秒. D02 の読み込みは numpy が古いと数分かかる.
   run を絞るなら `--runs R0009,R0010`.
   outflow は `--mode outflow` で同じ検定ができるが, outflow の PIV はノイズ床に近く谷も浅いので
   検出力は低い (参考扱い).
5. 出力 (`<data root>/derived/qc/qdip_jet_check/`):
   - `run_summary.csv`: run ごとの β, 区間, 判定, 長さの差, 有効率, 噴流軸
   - `window_ratios.csv`: 統計量 3 種 x x 区間 4 つの dip/ref, dip/pre, post/ref
   - `calibration.csv`: 水準ペア x 深さ窓の感度 n
   - `cfd_reference.csv`: CFD の流量一定基準
   - `summary.png`, `timeseries.png`
6. 結果をこの文書の §7 に追記する. 確定したら `doc/piv_conditions.md` §2d と論文側
   (`results.tex` §3.1 の実流量の記述, `paper/README.md` の投稿前項目 #2) を直す.

## 6. 残る弱点

1. 確認済みは 12 本中 5 本. high と low の残りは未確認 (→ WS).
2. LT では low が R0001 の 1 本だけなので, 感度 n の較正が弱い.
3. CFD 基準は h < a で導水路に非現実的な落下流があり, 選ばれる枝も実験と違う.
   使っているのは「流量一定で指標がどれだけ動くか」の幅だけ.
4. 表面しか見ていない. 噴流の鉛直分布の変化は見えない (ただし表面の速度と流束が両方とも
   変わらないまま流量だけ 1/3 になるとは考えにくい).
5. 判定できるのは谷 (44-50 mm) だけ. h > a での `Q_level` の上昇 (約 0.75 倍から 1.25 倍) は,
   流量一定の CFD でも指標が ±20-30% 動くので判定できない.

谷が流量低下でないとすると, 原因は水位計の読みか水槽側の貯留に絞られる (ポートの流量が保たれて
いるので, 給水側の貯留は否定される). どちらかを決めるのは静的体積較正: ポートを閉じた静水に
既知の体積 (例: 20 L ずつ) を注ぎ, 30-100 mm の読みを記録する.
